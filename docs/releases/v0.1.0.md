# v0.1.0

Release candidate for controller-owned Longhorn NFS gateway paths. This is not
a Macgrubernetes support announcement; integration remains gated on the release
consumer's rollout and additional failure testing.

## Pinned artifacts

- Controller (`linux/amd64`, `linux/arm64`):
  `docker.io/initialed85/longhorn-nfs-gateway@sha256:ae502ec89f0d349d4d4991b9dfa6d574c40ab8297a1bb2a953ab42c32dd53302`
- RWO Ganesha (Docker Hub `longhornio/nfs-ganesha:latest`, Ganesha 3.3):
  `docker.io/longhornio/nfs-ganesha@sha256:e633d9f2aa0281c6def298651a1b83a5dbb19f03f435f049aa1a757a53aa882b`
- RWX FSAL_PROXY_V4 helper (`linux/amd64`, `linux/arm64`):
  `docker.io/initialed85/nfs-ganesha-proxy-v4@sha256:d6ce0ab841c4f353aa4745007baa5f3b45c3dfceeb0f69a05edd6ba88dfaed1e`

The `deploy/` kustomization pins the controller digest. The controller default
and API/sample paths pin the Ganesha/proxy helper digests.

## Included behavior

- Explicit ClusterIP, NodePort, and LoadBalancer Service model with external
  address and NodePort status.
- Generic handoff status/annotations publish the reachable endpoint and actual
  protocol ports.
- RWX creates a Recreate bootstrap consumer to trigger the Longhorn
  share-manager, then discovers its Service/EndpointSlice and manages an
  FSAL_PROXY_V4 helper with endpoint-loss cleanup and recovery.
- Finalizer cleanup is owner-safe and never deletes PVCs or PVs.
- Failure-injection coverage includes unowned cleanup refusal, share-manager
  absence/loss, proxy cleanup, NodePort endpoint status, and source claim
  preservation.
